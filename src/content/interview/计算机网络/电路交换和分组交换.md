## 先区分资源怎样分配

### 核心区别

**电路交换（Circuit Switching）** 在通信双方开始传输数据之前，需要先沿路径预留通信资源，例如频段或固定时隙，通信结束后再释放。它可以与其他电路共享一条物理介质，并非每次通话都独占整根线缆。传统的公共电话交换网（PSTN）是其最典型的应用。

**分组交换（Packet Switching）** 将数据拆分为带有首部（源地址、目的地址、序号等控制信息）的小单元——分组（Packet），分组在网络中独立路由，逐跳以"存储-转发（Store and Forward）"方式传递，中间链路不被任何一对通信方独占，多个分组可共享同一条链路。现代互联网（IP 网络）即基于分组交换。

### 三个核心对比维度

| 维度 | 电路交换 | 分组交换 |
|------|---------|---------|
| **链路占用** | 独占，全程保持 | 共享，按需使用 |
| **空闲时的资源** | 已预留的容量通常不能临时让给其他电路 | 没有待发送分组时，链路可传输其他用户的分组 |
| **时延特性** | 需要建立电路，建立后带宽和时延较稳定 | IP 数据报无需预建连接，排队时间会随负载变化 |
| **适用场景** | 实时语音（电话） | 数据传输（互联网） |

### 存储转发机制

分组交换的核心是**存储转发**：中间节点（路由器）收到一个完整分组后，先缓存，再根据目的地址查找路由表，转发到下一跳。类比邮局：收到信件后先入库，再按目的地批量转发，而非为每封信专门开辟一条传输通道。

### 1. 电路交换：深入原理

#### 1.1 三个阶段

电路交换的完整通信过程分为三个严格的阶段：

```mermaid
sequenceDiagram
    participant A as 主叫方 A
    participant S1 as 交换节点 1
    participant S2 as 交换节点 2
    participant B as 被叫方 B

    rect rgb(230, 244, 255)
        Note over A,B: 阶段一：电路建立（Circuit Establishment）
        A->>S1: 呼叫请求（拨号）
        S1->>S2: 路由并预留资源
        S2->>B: 振铃
        B-->>A: 接听（电路建立完成）
    end

    rect rgb(230, 255, 230)
        Note over A,B: 阶段二：数据传输（Data Transfer）
        A-)B: 语音/数据（专用链路，全双工）
        Note over S1,S2: 资源被独占，无论是否有数据传输
    end

    rect rgb(255, 240, 230)
        Note over A,B: 阶段三：电路拆除（Circuit Teardown）
        A->>S1: 挂机信号
        S1->>S2: 释放资源
        S2->>B: 通知断开
    end
```

#### 1.2 频分多路复用（FDM）与时分多路复用（TDM）

在一条物理传输介质（如光缆）上，电路交换通过两种方式划分"电路"：

**频分多路复用（FDM，Frequency Division Multiplexing）**：将信道的总带宽划分为若干个频率子带，每路通话独占一个子带。无线广播、模拟电话即使用此方式。

**时分多路复用（TDM，Time Division Multiplexing）**：将时间划分为等长的时间槽（Time Slot），循环分配给各路通话，每路通话在固定时隙中传输。数字电话网络（如 E1/T1 线路）使用此方式——E1 标准将一条 2.048 Mbit/s 的线路划分为 32 个 64 kbit/s 的时隙。

```mermaid

    subgraph "FDM 频分复用"
        direction TB
        F["物理信道\n（总带宽）"]
        F --> F1["频段 1\n通话 A"]
        F --> F2["频段 2\n通话 B"]
        F --> F3["频段 3\n通话 C"]
        F --> F4["频段 4\n通话 D"]
    end

    subgraph "TDM 时分复用"
        direction TB
        T["物理信道\n（时间轴）"]

        T --> T2["时隙 2\n通话 B"]
        T --> T3["时隙 3\n通话 C"]
        T --> T4["时隙 1\n通话 A（下一轮）"]
    end
```

#### 1.3 为何线路利用率低？

在通信双方暂时没有数据发送时，电路预留的容量仍然存在。对突发数据业务，统计复用往往能更充分地使用链路；具体利用率取决于流量，不能用一个固定百分比概括。

### 2. 分组交换：深入原理

#### 2.1 分组的结构

每个分组（Packet）由两部分组成：

```
┌──────────────────────────────────────────────────────────┐
│                        分组（Packet）                      │
├──────────────────────┬───────────────────────────────────┤
│       首部（Header）  │           载荷（Payload）           │
│  源地址 | 目的地址   │                                     │
│  序号   | 校验和     │        实际数据（如 IP 数据报）       │
│  TTL    | 协议类型   │                                     │
└──────────────────────┴───────────────────────────────────┘
```

首部包含路由所需的所有控制信息，中间节点只需读取首部即可完成转发决策，无需关心载荷内容。

#### 2.2 存储转发的时延分析

存储转发是分组交换的核心机制，但它引入了**转发时延（Store-and-Forward Delay）**。假设：

- 链路带宽为 $R$ bps
- 分组大小为 $L$ bits
- 源到目的地共经过 $N$ 条链路（$N-1$ 个中间节点）

仅考虑一个分组，忽略传播、处理和排队时间，并假设每个节点收到整个分组后才转发，则各链路发送时间之和为：

$$T_{total} = N \cdot \frac{L}{R}$$

```mermaid
gantt
    title 存储转发时延示意（3条链路，L/R = 1个时间单位）
    dateFormat  X
    axisFormat %s

    section 链路 1（节点0→节点1）
    传输分组    :a1, 0, 1

    section 链路 2（节点1→节点2）
    等待接收完整分组  :crit, done, 0, 1
    传输分组          :a2, 1, 2

    section 链路 3（节点2→目的地）
    等待接收完整分组  :crit, done, 0, 2
    传输分组          :a3, 2, 3
```

总时延 = 3 × (L/R)，即 $N \times \frac{L}{R}$。

#### 2.3 统计多路复用：分组交换的效率优势

与电路交换的固定分配不同，分组交换使用**统计多路复用（Statistical Multiplexing）**：链路带宽按需分配，没有数据发送时不占用链路的发送时间，但设备仍可能维护会话、缓存等状态。

```mermaid
graph TB
    subgraph "电路交换（固定分配）"
        L1["链路带宽\n1 Mbps"]
        L1 --> U1["用户A：100Kbps（已分配，即使静默也占用）"]
        L1 --> U2["用户B：100Kbps（已分配，即使静默也占用）"]
        L1 --> U3["... 最多支持 10 个用户（100% 利用率假设下）"]
    end

    subgraph "分组交换（统计复用）"
        L2["链路带宽\n1 Mbps"]
        L2 --> V1["用户A：活跃时用满 100Kbps，静默时不占用"]
        L2 --> V2["用户B：同上"]
        L2 --> V3["... 若用户活跃概率为10%，可支持约35个用户\n（超过容量的概率约 0.000424）"]
    end
```

**数值示例（Kurose & Ross《Computer Networking》中的经典例子）**：

设链路带宽 1 Mbps，每个用户活跃时需要 100 kbps，但每个用户在某一时刻活跃的概率为 10%，并假设用户之间相互独立。

- 电路交换：最多支持 **10** 个用户（每人固定分配 100 kbps）
- 分组交换：若有 35 个用户，在某一时刻超过 10 个用户同时活跃的概率约为 0.0004，这个结果只表示该流量模型下超出容量的概率，不能直接承诺 35 个用户始终无排队或丢包

#### 2.4 分组交换的四种时延

分组在网络中经历的端到端时延由四部分叠加而成：

```mermaid
graph LR
    A["分组到达\n节点队列"] --> P["处理时延\nd_proc\n（检验首部、查路由表）"]
    P --> Q["排队时延\nd_queue\n（等待链路空闲）"]
    Q --> T["传输时延\nd_trans = L/R\n（将分组比特推入链路）"]
    T --> PR["传播时延\nd_prop = d/s\n（比特在介质中传播）"]
    PR --> B["到达下一节点"]

    style Q fill:#ffd43b,stroke:#fab005
```

| 时延类型 | 公式 | 影响因素 | 典型量级 |
|---------|------|---------|---------|
| **处理时延** $d_{proc}$ | — | 路由器性能 | 微秒级 |
| **排队时延** $d_{queue}$ | 取决于流量强度 | 网络拥塞程度 | 微秒～毫秒 |
| **传输时延** $d_{trans}$ | $L / R$ | 分组大小、链路带宽 | 微秒～毫秒 |
| **传播时延** $d_{prop}$ | $d / s$（$s \approx 2\times10^8$ m/s） | 物理距离 | 毫秒级（跨洲） |

> 常见混淆：**传输时延**是把分组的所有比特"推入"链路所需的时间，取决于分组大小和链路带宽；**传播时延**是一个比特从链路一端传播到另一端所需的时间，取决于物理距离。两者量纲相同但含义截然不同。

### 3. 虚电路交换：介于两者之间的折中

现实中还存在一种折中方案——**虚电路交换（Virtual Circuit Switching）**，兼具两种交换方式的部分特性。

```mermaid
graph LR
    A["电路交换"] -->|"不固定预留整条链路容量\n保留连接建立和固定路径"| VC["虚电路交换"]
    B["分组交换"] -->|"去掉无连接自由路由\n加入逻辑连接概念"| VC
```

| 特性 | 电路交换 | 虚电路交换 | 数据报分组交换 |
|------|---------|-----------|------------|
| 需要建立连接 | ✅ 物理连接 | ✅ 逻辑连接 | ❌ |
| 固定路径 | ✅ | ✅ | ❌（逐包独立路由） |
| 独占资源 | ✅ | ❌（共享） | ❌ |
| 分组携带地址 | 无需 | 仅携带 VCI 标识 | 完整目的地址 |
| 代表技术 | PSTN | ATM、X.25、MPLS | IP 网络 |

ATM（Asynchronous Transfer Mode，异步传输模式）是虚电路交换的典型代表，曾被业界寄望为"下一代网络"的基础技术，但最终输给了更简单灵活的 IP 分组交换。MPLS（多协议标签交换）则是目前仍大量用于运营商骨干网的虚电路技术。

### 4. 现代网络中的演进

#### 4.1 VoIP：在分组交换网上模拟电路交换体验

随着互联网普及，传统 PSTN 电路交换网络逐渐被基于 IP 的语音通话（VoIP，Voice over IP）所取代。Skype、微信语音、企业 SIP 电话系统均属此类。

VoIP 本质上是在分组交换网上传输实时音频，面临的核心挑战正是分组交换的天然缺陷——**不确定的排队时延和抖动（Jitter）**。解决方案包括：

- **RTP 协议**（Real-time Transport Protocol）：专为实时音视频设计的传输协议
- **抖动缓冲区（Jitter Buffer）**：在接收端缓存少量数据包，平滑时延抖动
- **QoS 机制**：通过 DSCP 标记、优先队列等手段给语音包更高的转发优先级
