FFmpeg 处理任务由四部分构成：输入声明、Stream 选择、数据路径和输出约束。命令行参数负责把这些设计信息绑定到具体输入与输出。

## 处理模型

```mermaid
flowchart LR
  A[输入文件 / 网络流 / 设备] --> B[Demux 解封装]
  B --> C{处理方式}
  C -->|不改内容| D[Stream Copy]
  C -->|需要修改| E[Decode 解码]
  E --> F[Filter 滤镜]
  F --> G[Encode 编码]
  D --> H[Mux 封装]
  G --> H
  H --> I[输出文件 / 推流地址]
```

分叉条件是输出 Stream 的内容是否发生变化。内容不变时可采用 Stream Copy；画面、音频采样或编码格式发生变化时，对应 Stream 进入解码、滤镜和编码链路。

## 设计输入与产出

| 设计项 | 输入信息 | 产出 |
| --- | --- | --- |
| 媒体描述 | 容器、Stream、编码、时间戳、构建能力 | 可追溯的输入事实 |
| Stream 选择 | 类型、索引、语言、可选性 | 当前输出的 Stream 集合 |
| 数据路径 | 内容是否变化、容器兼容性、资源预算 | Copy、Encode 或 Filtergraph 路径 |
| 输出契约 | 容器、编码、像素格式、码率、时长、播放端 | 可验证的媒体规格 |
| 运行验收 | 退出码、探测结果、完整解码、客户端表现 | 结构与兼容性证据 |

CRF、码率、时间戳、协议和硬件加速属于具体策略，不改变上述边界。

## 命令模型

FFmpeg 的基本语法是：

```text
ffmpeg [全局参数] {[输入参数] -i 输入} ... {[输出参数] 输出} ...
```

例如：

```powershell
ffmpeg -hide_banner -ss 00:00:05 -i input.mp4 -map 0:v:0 -map 0:a:0? -t 10 -c:v libx264 -crf 23 -c:a aac output.mp4
```

按文件边界解析：

| 片段 | 含义 |
| --- | --- |
| `-hide_banner` | 全局参数，精简启动日志 |
| `-ss 00:00:05` | 输入参数，从输入约第 5 秒开始定位 |
| `-i input.mp4` | 第 0 个输入 |
| `-map 0:v:0` | 选择第 0 个输入的第一条视频流 |
| `-map 0:a:0?` | 音频存在就选择，不存在也不报错 |
| `-t 10` | 输出约 10 秒 |
| `-c:v libx264 -crf 23` | 视频使用 H.264 软件编码并设置恒定质量 |
| `-c:a aac` | 音频编码为 AAC |
| `output.mp4` | 当前输出 URL |

除全局选项外，选项作用于后面紧邻的输入或输出文件。多输入、多输出命令按文件边界分组；上一输出的选项不会隐式延伸到下一输出。

## 处理规格与命令映射

### 输入事实

```powershell
ffprobe -v error -show_format -show_streams -of json input.mp4
```

输入记录包含：

- 有哪些视频、音频、字幕流；
- 编码和像素格式是什么；
- 分辨率、帧率、采样率、声道数是多少；
- 时长是否可信，输入是否存在异常时间戳。

### 输出约束

“压缩视频”缺少可验证条件。可执行的输出规格如下：

```text
保留第一条视频和可选的第一条音频；
输出 MP4；视频编码 H.264、最长边不超过 1280；
音频 AAC 128 kbit/s；文件适合网页渐进播放。
```

### Stream 选择

自动化脚本采用显式 `-map`，避免输入 Stream 数量或顺序变化后改变输出结构：

```powershell
ffmpeg -i input.mp4 -map 0:v:0 -map 0:a:0? ... output.mp4
```

`?` 使映射在目标 Stream 不存在时忽略该项；是否允许缺失由业务失败策略定义。

### 处理路径

当编码内容保持不变且目标容器支持原编码时，处理路径为 Stream Copy：

```powershell
ffmpeg -i input.mkv -map 0 -c copy output.mkv
```

缩放、加水印、改变帧率和烧录字幕会改动视频 Frame，视频必须重编码；音频在容器兼容时仍可复制。改变采样率、声道或音量会改动音频采样，音频必须重编码。

### 编码与封装

```powershell
ffmpeg -i input.mp4 -map 0:v:0 -map 0:a:0? -vf "scale=w=1280:h=-2:force_original_aspect_ratio=decrease" -c:v libx264 -crf 23 -preset medium -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart output.mp4
```

该配置面向常见网页 MP4：`yuv420p` 用于兼容传统播放环境，`+faststart` 将 MP4 索引移动到文件前部。归档、HDR 和直播采用不同的输出契约，不复用该配置。

### 结果验收

```powershell
ffprobe -v error -show_entries format=duration,size,format_name -show_entries stream=index,codec_type,codec_name,width,height,pix_fmt,avg_frame_rate,sample_rate,channels -of json output.mp4
```

`ffprobe` 负责结构证据；目标播放器负责解码、同步、方向、色彩和兼容性证据。两者不能互相替代。

## 处理策略矩阵

| 需求 | 是否重编码 | 核心写法 |
| --- | --- | --- |
| 只换容器 | 通常否 | `-map 0 -c copy` |
| 改编码或压缩 | 是 | `-c:v libx264 -crf 23` |
| 缩放、裁剪、水印 | 对应流必须 | `-vf` 或 `-filter_complex` |
| 替换音频 | 视频可复制，音频视格式决定 | 两个 `-i` 配合 `-map` |
| 快速切片 | 可不重编码，但切点受关键帧影响 | 输入前 `-ss`、`-c copy` |
| 精确切片 | 是 | 解码后输出指定时长 |
| RTSP 连通性验证 | 不必保存 | `-rtsp_transport tcp`、`-f null -` |
| 程序读取媒体信息 | 否 | `ffprobe -of json` |

## 自动化接口约束

| 项目 | 约束 |
| --- | --- |
| 进程 | 固定可执行文件，设置超时、取消和进程树清理 |
| 参数 | 文件名、滤镜和网络地址作为受控参数传入，不拼接不可信 Shell 文本 |
| 资源 | 限制并发、运行时长、输出目录和磁盘占用 |
| 日志 | 保留版本、退出码和必要 stderr；URL、Header 与凭据脱敏 |
| 输出 | 完成结构探测；关键业务增加完整解码或目标客户端验收 |
| 硬件 | 记录设备、驱动和编码器，定义不可用时的回退策略 |

## 语义边界

| 命题 | 约束 |
| --- | --- |
| 改扩展名就是格式转换 | 扩展名不能改变容器结构或编码内容 |
| `-c copy` 会降低画质 | 它复制压缩 Packet，不重新编码；但可能与目标容器不兼容 |
| CRF 是百分比画质 | CRF 是编码器相关的质量控制值，不能跨编码器直接比较 |
| 码率越高一定越清晰 | 还取决于编码器、内容复杂度、分辨率、帧率和编码设置 |
| `-r` 放哪里都一样 | 输入和输出位置语义不同；普通文件改帧率更推荐 `fps` 滤镜明确生成帧 |
| FFmpeg 退出码为 0 就完成验收 | 还要核对结构、可解码性、播放兼容与业务目标 |
| RTSP 打不开就是编码问题 | 网络、鉴权、URL、设备状态和传输方式都可能是原因 |

## 运行记录

| 阶段 | 记录内容 | 验收依据 |
| --- | --- | --- |
| 输入 | `ffprobe` 结果、FFmpeg 版本与构建能力 | 输入事实可复现 |
| 设计 | Stream 映射、数据路径、输出容器与编码参数 | 处理规格完整 |
| 执行 | 完整命令、退出码、必要 stderr、耗时与资源占用 | 任务执行可追踪 |
| 输出 | Stream 结构、完整解码结果、体积与质量指标 | 输出符合媒体规格 |
| 客户端 | 播放器、浏览器或实时链路的环境和结果 | 目标环境兼容 |
