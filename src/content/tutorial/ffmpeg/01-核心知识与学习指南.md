这一篇只做三件事：确认工具在、看懂命令长什么样、成功做出一个输出文件。滤镜、时间戳和多轨先放到后面。

## 三个程序，三种活

可以把一次媒体处理想成寄快递：

| 工具 | 人话 | 最常见的动作 |
| --- | --- | --- |
| `ffprobe` | 先看运单：箱子里有什么 | 看有哪些流、编码、分辨率、时长 |
| `ffmpeg` | 拆箱、加工、再装箱 | 换容器、转码、剪切、推流 |
| `ffplay` | 当场打开验货 | 快速确认画面和声音 |

它们是三个可独立运行的程序，不是同一个命令的三个参数。先记成：`ffprobe` 看，`ffmpeg` 做，`ffplay` 播。

```mermaid
flowchart LR
  I[输入媒体] --> P[ffprobe<br/>看结构]
  I --> F[ffmpeg<br/>处理并输出]
  F --> O[输出媒体]
  O --> V[ffplay<br/>播放验收]
  P -. 提供编码和流的事实 .-> F
```

这不是强制步骤，而是排错时最稳的协作关系：先看清楚再动手。`ffplay` 只负责观察结果，不能代替 `ffprobe` 的结构检查。

## 检查安装和能力

```powershell
ffmpeg -version
ffprobe -version
ffplay -version
```

三条都能返回版本，说明程序在 PATH 里。版本信息里的构建配置决定了有哪些编码器、滤镜和协议。要用某个编码器前，先问当前机器：

```powershell
ffmpeg -hide_banner -encoders 2>&1 | Select-String "libx264|libx265|aac"
```

要用某个滤镜时同样查：

```powershell
ffmpeg -hide_banner -filters 2>&1 | Select-String "scale|fps|overlay"
```

`2>&1` 把 FFmpeg 写到错误输出的日志并进流水线，`Select-String` 只留下你关心的名字。

| 你看到的提示 | 先查什么 |
| --- | --- |
| 不是内部或外部命令 | 没安装，或 `bin` 不在 PATH |
| `Unknown encoder` | 当前构建没有这个编码器，或名称写错 |
| 打不开输入文件 | 路径、权限、文件是否存在；还不是参数写复杂了 |

## 命令长什么样

官方骨架可以写成：

```text
ffmpeg [全局选项] [输入选项] -i 输入 [输出选项] 输出
```

最小例子：

```powershell
ffmpeg -i input.mp4 output.mkv
```

拆开看：

```text
ffmpeg        程序
-i input.mp4  输入从哪里来
output.mkv    输出写到哪里
```

```mermaid
flowchart LR
  A[全局选项] --> B[输入选项]
  B --> C[-i 输入]
  C --> D[输出选项]
  D --> E[输出文件]
```

`-i` 声明输入，最后一个路径是输出。输出扩展名通常帮助 FFmpeg 选择容器（Muxer），但**扩展名不会改编码**。要不要重新压缩，由 `-c`、滤镜和目标容器共同决定。

多数选项要放在它作用的输入或输出旁边。多输入、多输出的作用域到第 04、05 篇再展开。

## 第一次查看和播放

```powershell
ffplay input.mp4
```

这条命令只播放，不写文件。如果只想读信息，不要依赖 `ffmpeg -i` 打出来的人类日志，使用：

```powershell
ffprobe -hide_banner input.mp4
```

输出里先找 `Duration`、`Stream`、视频分辨率和音频编码。字段含义见第 02 篇。

## 第一次转封装：不改变媒体内容

目标只是换容器，并且目标容器能装原来的流时：

```powershell
ffmpeg -i input.mp4 -c copy output.mkv
```

这条命令在做什么：把压缩后的数据原样搬进新容器，不解码、不重压。

这里的 `copy` 不是编码器名字，而是“复制压缩包”。它通常很快，也不会多一次有损编码；但如果目标容器不支持某条流，复制会失败。

完成后检查容器里到底是什么：

```powershell
ffprobe -v error -show_format -show_streams -of json output.mkv
```

## 第一次转码：改变编码

例如把视频压成 H.264、音频压成 AAC：

```powershell
ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4
```

这条命令会先解码，再按新编码压回去。速度、体积和画质取决于编码器和参数。若本机没有 `libx264`，先从 `-encoders` 列表挑实际有的编码器。

不要只改扩展名来“转换格式”。`Rename-Item input.mkv output.mp4` 只改名字，字节不会变。

## 别覆盖已有文件

学习时让输出用新文件名最安全。脚本需要明确覆盖策略时：

```powershell
ffmpeg -n -i input.mp4 -c copy output.mkv
```

| 选项 | 输出已存在时 |
| --- | --- |
| `-n` | 失败并退出 |
| `-y` | 直接覆盖 |

两者都不是媒体处理本身的必要参数。本教程示例默认不加 `-y`。

## 这一篇的最小检查清单

1. `ffmpeg -version` 能返回版本。
2. `ffprobe input.mp4` 能读到输入。
3. 至少成功执行一次 `-c copy` 或转码命令。
4. 用 `ffprobe` 再看输出，并用 `ffplay` 试听/观看。

第 2 步失败时，先处理路径、权限、文件完整性或输入协议，不要直接往命令里堆参数。
