## 先分清两条链

GB28181 接入包含 SIP 信令和媒体传输。ZLM 的 RTP 接口接收媒体，并不自动替你建立完整的设备注册、目录和点播平台。设备编号、通道编号也不是可直接拉取的视频 URL。

```text
信令：设备 REGISTER → SIP 平台鉴权 → Catalog / Keepalive → INVITE / SDP → 200 / ACK
媒体：设备编码 → PS 封装 → RTP → ZLM 接收 → 解复用 → WebRTC → 浏览器
结束：SIP BYE → 停止发送 → 关闭本次 RTP 接收器
```

本篇提供可执行的 **PS/RTP 媒体核心**。用已经运行的 ZLM 模拟媒体发送端，不实现一个简化鉴权后容易被误用于生产的 SIP 服务。实际相机接入还需 SIP 程序，下面给出它与媒体核心衔接的顺序。

## 创建模拟视频源

按[准备篇](/tutorials/tzlm-setup/)准备 Python、工具和 ZLM。窗口 A 运行：

```shell
ffmpeg -re -f lavfi -i testsrc2=size=640x360:rate=15 -t 600 -an -c:v libx264 -preset ultrafast -tune zerolatency -pix_fmt yuv420p -g 15 -bf 0 -f flv rtmp://127.0.0.1:1935/sim/camera
```

窗口 B：

```shell
python zlm_core.py gb-media --app sim --stream camera --seconds 180
```

本机程序会依次执行：

1. openRtpServer：port=0 让 ZLM 分配可用端口，tcp_mode=0 使用 UDP，stream_id 使用随机值。
2. startSendRtp：把 sim/camera 编码数据封装为 PS，以 RTP payload type 96 发到该端口；use_ps=1、is_udp=1。
3. 等待 rtp/随机流名 注册，打印当前播放地址。
4. 180 秒后先 stopSendRtp，再 closeRtpServer，只清理本次 SSRC 和接收器。

这个“ZLM 发给 ZLM”的回环实验是媒体发送器替身，不包含 SIP，也不是物理国标设备验收。程序里的随机 SSRC 仅用于实验匹配，不能作为生产国标 SSRC 分配规则。

## 在浏览器和 Python 中读取

复制程序打印的 browser 地址，打开 ZLM 页面并点击播放。流名每次不同，不要复用上一次地址。

在第三个窗口用打印的 RTSP 地址读取轨道和像素，例如将下面的 YOUR_STREAM 换成当前 gb_ 开头的流名：

```shell
python zlm_core.py list --app rtp --stream YOUR_STREAM
python zlm_core.py frame --url rtsp://127.0.0.1:8554/rtp/YOUR_STREAM --output gb-frame.ppm
```

应看到 H.264、640×360 和持续变化的图案。ZLM 先处理 RTP 序号、时间戳和负载，再解复用 PS，从 PES 中取得 H.264 压缩数据；浏览器或 FFmpeg 解码后才得到像素。PS、RTP、H.264 分别属于不同层，不能互相替代。

## 接真实设备时如何接上 SIP

| 步骤 | 信令程序负责 | 与 ZLM 的衔接 |
| --- | --- | --- |
| 注册 | REGISTER、Digest 校验、有效期、设备地址 | 此时还没有视频 |
| 目录 | Catalog、设备/通道编号、Keepalive | 不把目录在线当作收帧 |
| 点播准备 | 确定通道与本次 SSRC | 先 openRtpServer，保留接收器归属 |
| 邀请 | INVITE SDP 声明接收 IP/端口、PS/90000、传输方式及 SSRC | 端口必须是本次实际打开的端口 |
| 建立 | 处理 200、校验 SDP、发送 ACK | 等待目标媒体注册和轨道出现 |
| 播放 | 生成授权后的播放入口 | 浏览器访问 ZLM WebRTC |
| 结束 | BYE、超时/失败清理 | closeRtpServer，确认资源释放 |

设备断线、INVITE 超时、迟到的 200、取消与并发点播都需要状态机，不能无限重发。本篇只演示 UDP 媒体，不声称已覆盖 TCP 主动/被动、级联、回放、PTZ、音频和不同厂商互通。

## 常见错误

- openRtpServer 成功却没有轨道：只是打开了接收器；检查发送目标、UDP、防火墙、SSRC、PS 负载和实际包到达。
- 收到 RTP 仍不能播放：确认负载是协商的 PS，而非把裸 H.264 当 PS；检查 payload type 和 SDP 编码描述。
- SIP 注册在线但没图：注册证明信令可达，不证明已发起 INVITE 或媒体通道可达。
- 关闭页面后还占端口：浏览器关闭不等于 SIP BYE；业务程序需管理引用和清理责任。
